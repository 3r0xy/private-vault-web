# note v1.7

Личный web-vault на GitHub Pages с хранением заметок и вложений в отдельном private GitHub repository.

## Файлы приложения

- `index.html` — интерфейс
- `styles.css` — стили
- `app-v1.7.js` — редактор, GitHub API, проводник, граф и недельный планер
- `domain.mjs` — ссылки, перенос папок, объединение задач и даты подготовки
- `task-hub.mjs` — будущие дела и проекты
- `tests/` — проверки логики и браузерные сценарии с вымышленным vault
- `docs/planning.md` — формат задач и правила планирования из чата

Предыдущие `app*.js` оставлены как архив версий. Текущий HTML загружает только `app-v1.7.js`.

## Стек и запуск

HTML, CSS, JavaScript modules. CodeMirror 6 загружается с esm.sh, D3 7 — с jsDelivr. Сборка и установка зависимостей для сайта не нужны. Для локального просмотра запускайте HTTP-сервер в корне; открытие через `file://` не подходит для модулей.

## Новое в v1.7

- Граф читает сохранённые заметки и открытые черновики, wiki-ссылки и внутренние Markdown-ссылки. Поддерживает относительные пути, алиасы, заголовки и кириллицу; ошибки чтения видны пользователю.
- Папка переименовывается одним Git-коммитом: новые пути и удаление старых становятся видны одновременно. Изображения, `.gitkeep` и ссылки переносятся вместе. Конкурентное изменение отменяет обновление ветки.
- Папки по умолчанию свёрнуты; состояние запоминается отдельно для каждого vault.
- Категории: «Встречи», «Общее», «Остальное». Старые идентификаторы сохранены, существующие задачи остаются на месте.
- Переключение недели сначала сохраняет изменения. Закрытие сохраняет исходную неделю, итоги и следующую неделю одним коммитом. Разовые дела переносятся только по выбору пользователя; ежедневные и еженедельные появляются автоматически. Следующая неделя объединяется с существующими задачами; повторное закрытие не дублирует перенос.
- «Будущие дела и проекты»: Медиакружок, ВКР, СФУ и новые проекты пользователя. Поддерживает задачи без даты, датированные задачи, постоянные ежедневные/еженедельные дела и события с подготовкой.
- Для подготовки указываются дни, часы и шаги. Шаги распределяются до события и сохраняются в соответствующие недели. Неизвестная подготовка помечается «уточнить». Созданные шаги редактируются отдельно.

## Обновление сайта

Обновляйте вместе `index.html`, `styles.css`, `app-v1.7.js`, `domain.mjs`, `task-hub.mjs`. После коммита в опубликованную ветку дождитесь GitHub Pages deployment и обновите браузер (`Ctrl + Shift + R`). GitHub Desktop подходит для Fetch/Pull, просмотра изменений, Commit/Push и истории версий.

## Проверки

Для проверок логики нужен Node.js:

```sh
node --test tests/domain.test.mjs
```

Браузерные проверки дополнительно используют Playwright и Chromium. Можно указать `PLAYWRIGHT_MODULE` для существующей установки Playwright и `BROWSER_EXECUTABLE` для установленного браузера:

```sh
node tests/browser.test.cjs
```

Все GitHub API запросы в браузерных проверках перехватываются; используются вымышленные заметки и тестовый token. Скриншоты сохраняются рядом с папкой проекта.

## Vault size

В нижней строке состояния показана ненавязчивая плашка `Vault: X / 10 GB`. Это приблизительная сумма текущих файлов, видимых через GitHub tree API. `10 GB` — рекомендованный GitHub ориентир размера репозитория, а не квота бесплатного тарифа; история Git может занимать дополнительное место.

## Безопасность

Токен не должен попадать в этот public-репозиторий. Используй fine-grained token только для `my-private-vault` с разрешением `Contents: Read and write` и храни его в менеджере паролей.
