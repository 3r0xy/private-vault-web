# Работа с делами и проектами

## Планирование из чата

1. Уточнить дату события (и время, если нужно), название и проект.
2. Спросить, за сколько дней начать подготовку и сколько часов суммарно понадобится. Не придумывать оценку времени за пользователя.
3. Согласовать шаги подготовки и распределение времени. До ответа хранить событие с пустыми `prepDays`/`prepHours` и пометкой «уточнить».
4. Сохранить событие и шаги в приватном vault; создать/обновить соответствующие недели, сохраняя существующие задачи и выполнение.

Изменение дел через чат требует доступа к приватному vault. Доступ к репозиторию интерфейса сам по себе не даёт доступ к заметкам. Документ описывает процесс и не разрешает выполнение задач или отправку сообщений без запроса пользователя.

## Файлы в приватном vault

- `planner/projects.md` — проекты, будущие дела, события и постоянные задачи.
- `planner/weeks/YYYY-MM-DD.md` — неделя; дата — понедельник.
- `planner/stats/YYYY-MM-DD.md` — сохранённые итоги недели.

Файлы содержат читаемый Markdown и служебный комментарий с UTF-8 JSON в Base64. Для интерфейса комментарий — источник структурированных данных. При программной правке обновляйте и список, и комментарий: изменение только видимого Markdown не меняет данные интерфейса.

## Проекты и будущие дела

Комментарий: `<!-- NOTE_PROJECTS_STATE:BASE64 -->`. Данные содержат `version: 1`, массив `projects` (объекты `id`, `name`) и массив `tasks`.

Поля задачи:

- `id` — уникальный стабильный идентификатор.
- `text` — название с необязательными wiki-ссылками.
- `projectId` — проект; начальные проекты: `media`, `vkr`, `sfu`.
- `kind` — `task` или `event`.
- `date` — ISO дата `YYYY-MM-DD`; для дела без даты пустая строка.
- `time` — `HH:mm` или пустая строка; `duration` — минуты.
- `section` — `meetings` (Встречи), `general` (Общее), `health` (Остальное). Идентификатор `health` сохранён для совместимости.
- `repeat` — `none`, `daily`, `weekly`; `done` — завершён ли источник задачи.
- `prepDays` — целое число дней до события; `prepHours` — суммарные часы; `prepSteps` — шаги с разделением новой строкой. Неизвестные оценки — `null`.
- `eventId` — для шага подготовки, ссылка на событие.
- `updatedAt` — ISO timestamp версии шаблона.

Постоянные задачи появляются в неделях начиная с указанной даты. Завершение постоянного дела в разделе проектов прекращает будущие появления; чекбокс в неделе отмечает отдельное появление. Изменение шаблона обновляет незавершённые появления в открытых неделях; закрытые недели и выполненные дела сохраняют историю.

## Неделя

Комментарий: `<!-- NOTE_PLANNER_STATE:BASE64 -->`. JSON содержит `version`, `weekStart`, `createdAt`, `tasks`; после закрытия — `closedAt`, `nextWeek`, `carriedTaskIds`.

Поля задачи: `id`, `day` (0 = понедельник, 6 = воскресенье), `section`, `text`, `time`, `duration`, `repeat`, `recurrenceId`, `done`, `order`. Дополнительные поля сохраняются при чтении:

- `projectId` — проект.
- `hubTaskId` — задача/шаблон из раздела проектов.
- `originKey` — стабильная идентичность появления: `hub:TASK_ID:YYYY-MM-DD` или `carry:SOURCE_WEEK:TASK_ID`.
- `hubRevision` — версия шаблона, позволяющая сохранять изменения отдельного недельного появления до изменения шаблона.

Закрытие не удаляет исходные задачи. Пользователь выбирает разовые дела для переноса; повторяющиеся переносятся автоматически. Следующая неделя объединяется с существующими задачами; повторное закрытие добавляет только отсутствующие появления.

## Сохранение

Папка, закрытие недели и план проекта сохраняются через Git Trees/Commits API, затем ветка обновляется один раз без force. Перед записью проверяются SHA исходных файлов; конкурентные изменения приводят к ошибке, а не к перезаписи.

При ручной работе через GitHub API используйте актуальные SHA и те же правила объединения. Не заменяйте недельный файл пустым шаблоном и не удаляйте метаданные.
